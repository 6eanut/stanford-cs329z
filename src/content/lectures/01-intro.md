## 本讲要解决什么问题

大语言模型能够回答问题，但“智能体”还需要持续观察环境、选择行动、使用工具，并根据结果调整下一步。第一讲给出全课程的地图：智能体从哪里来、今天的系统由什么组成，以及为什么一个看似会做事的演示仍离可靠部署很远。

课程同时强调模型视角和系统视角。前者关心模型如何训练、提示和评估；后者关心工具、接口、运行环境与基础设施。学习智能体工程，需要把两者接在一起，并通过实际构建和评估来检验想法。

## 一、从“行动者”到 LLM 智能体

“Agent”本义是行动者。早期人工智能已经研究自主行动、任务协商和多个行动者组成的系统。20 世纪 90 年代，研究者用**自主性、社会能力、反应性和主动性**描述智能体；Russell 与 Norvig 的经典定义则强调：智能体通过传感器感知环境，通过执行器作用于环境。强化学习随后把这一思想写成清楚的**智能体—环境循环**：观察状态，采取行动，获得新观察与反馈。

LLM 时代改变的是行动的接口。模型能用自然语言理解目标、分解任务、阅读工具返回的文本，并生成下一步操作。讲义以 GPT-3 的上下文学习、MRKL 的模块化推理和工具使用，以及后来的 LLM 智能体为线索，说明“模型能力提升”与“智能体能力提升”相关，但不是同一个问题。即使模型很强，工具、上下文和运行流程的设计也会决定它能否完成任务。

## 二、一个智能体的基本闭环

可以把智能体想成五个相互连接的部分：

1. **LLM 核心**理解目标，生成中间推理和下一步决策。
2. **规划与推理**将观察转成行动，并在失败后修正计划。
3. **记忆**保存当前上下文之外仍有用的经历、知识和技能。
4. **工具**连接搜索、计算器、代码执行、文件操作等外部能力。
5. **环境**是桌面、浏览器、数据库、游戏或用户所在的外部世界；行动改变环境，环境再产生新的观察。

这不是一条只运行一次的流水线，而是 `观察 → 思考 → 行动 → 新观察` 的循环。以“做菜时发现盐用完了”为例，系统不能机械地重复“加盐”；它需要推断菜需要咸味、发现酱油可替代、打开橱柜确认。中间推理帮助它跨过“观察”与“具体动作”之间的距离，但推理本身也可能出错，因此仍需查看行动结果。

### 推理为何需要行动校验

讲义中的 Apple Remote 问答展示了这一点。只在内部逐步推理的模型，误以为设备原本控制的是 Apple TV，于是给出错误答案。ReAct 则交替执行 `Thought`、`Act`、`Obs`：先搜索 Apple Remote，得知它最初用于 Front Row；再查 Front Row，最终找到“键盘功能键”这一答案。外部观察纠正了第一步可能出现的幻觉。

还有几种补充方法：**自洽性**让模型产生多条推理路径，再汇总一致答案；**Reflexion**把失败轨迹压缩为自然语言反思，供以后参考；**多智能体辩论**让不同智能体交换意见。它们都试图改善决策，但不能替代真实环境中的验证。

## 三、记忆与工具如何进入系统

上下文窗口放不下无限长的事件流，即使放得下，模型也未必能找到相关部分。讲义按保存的**内容**区分三类长期记忆：

| 类型 | 保存什么 | 常见读写方式 |
| --- | --- | --- |
| 情景记忆（episodic） | 过去发生的事件与经验 | 追加事件，按相关性检索 |
| 语义记忆（semantic） | 从事件中归纳的知识 | 归纳写入，再检索使用 |
| 程序记忆（procedural） | 可复用的技能或步骤 | 保存代码化技能，以嵌入检索 |

工具则让模型越过纯文本生成的边界。Toolformer 研究模型如何决定**何时调用哪个 API、传入什么参数、如何利用返回结果**。在工程实现中，一次工具调用应经过“选择工具 → 填写参数 → 校验结构 → 执行 → 将结果放回上下文”。例如要知道 `test.py` 的内容，模型选 `read_file`，提供 `path` 字段，系统先校验，再执行读取。工具返回的信息成为下一轮观察，而不是模型凭空假设的事实。

## 四、工作流、智能体与复合 AI 系统

讲义把工作流和智能体都视为“LLM 加其他组件”的**复合 AI 系统**。差别在于谁决定步骤：工作流的步骤由代码预先固定；智能体由模型根据任务与观察决定下一步。两者都可能有用，选择取决于任务需要多少动态决策。

检索增强生成（RAG）是一个基础例子：先检索相关文档，再把内容加入问题上下文，最后生成有依据的回答。MCP 等协议帮助模型与外部工具连接。设计时还要同时考虑讲义提出的三层：**系统**（架构与工具）、**数据**（训练样例、演示与上下文）、**评估**（任务和指标）。只调整提示词而不检查另外两层，很难判断改进是否真实。

## 五、为什么“完成任务”还不够

智能体要经过多个步骤，单步错误会叠加；长任务又让上下文不断增长和漂移。讲义将主要挑战归为可靠性、训练、长时程任务、安全和评估。可靠性至少包含三件事：相同任务多次运行是否稳定；小幅改变提示或工具后是否稳健；失败是否可解释、可恢复。

**任务完成率不等于安全合规率。** 一个系统可能完成用户目标，却泄露无权访问的资料、被网页弹窗诱导偏离任务，或与其他智能体发生不符合目标的协同行为。因此评估不仅要问“能否成功”，也要检查失败类型、隐私边界与对抗输入下的行为。
